# 配置与功能指南

简体中文 | [English](configuration.md)

[返回项目首页](../README_ZH.md) · [开发者高级配置](../packages/qwen-live-harness/README_ZH.md#高级配置参考)

完成初始化后，大部分日常操作都可以在语音卡片的**设置**中完成。修改模型、API key、画面清晰度等高级选项时，需要打开配置文件。

## 想改什么，去哪里改

| 我想……                           | 在哪里操作                                     |
| -------------------------------- | ---------------------------------------------- |
| 换一个麦克风                     | 设置 → 声音 → 麦克风                           |
| 在屏幕和摄像头之间切换           | 设置 → 视频来源                                |
| 在通话中持续分享画面             | 设置 → 采集模式 → 实时画面                     |
| 选择要看的显示器                 | 设置 → 视频来源 → 显示器                       |
| 开关记忆、换记忆库、修改记忆名称 | 设置 → 个性化 → 记忆                           |
| 更换主题配色                     | 设置 → 个性化 → 配色                           |
| 切换中文／英文、浅色／深色       | 设置 → 个性化 → 语言／外观                     |
| 选择后台请求如何授权             | 设置 → 后台 Harness 授权                       |
| 修改模型、API key、分辨率、帧率  | 设置 → 打开配置文件                            |
| 开始或结束通话                   | 语音卡片上的开始／结束通话按钮，或 `Command+E` |

## 修改配置，只需五步

1. **打开文件。** 在设置中点击**打开配置文件**，会用电脑默认的编辑器打开 `config.json`。
2. **留一份备份。** 第一次修改前，把文件复制一份，例如 `config.backup.json`。
3. **只改需要的字段。** 按下文示例找到同名设置，保留文件里的其他内容。
4. **保存文件。** 配置使用 JSON：文字加双引号，不写注释，最后一项后面不要留逗号。
5. **退出并重启。** 退出 Qwen Live Harness 后重新打开；仅结束通话不会重新读取整个配置。

默认文件在 `~/.qwen-live-harness/config.json`。如果设置了其他配置目录，设置页会打开当前使用的文件。

无法打开设置时，也可以在 Finder 的“前往文件夹”中输入 `~/.qwen-live-harness`，再用文本编辑器打开 `config.json`。配置可能含有 API key，分享副本前请先移除密钥。

下文的 JSON 都是**要合并到现有文件的片段**，不是让你用片段覆盖整个文件。例如，已经有 `memory` 时，在它里面修改对应内容，不要再添加第二个 `memory`。

重新运行初始化并确认覆盖会重新生成配置。只是想调整一两个选项时，直接编辑更方便，也更容易保留已有设置。

## 模型、API key 与服务地域

第一次配置，推荐使用初始化向导：

```sh
qwen-live-harness init
```

向导会询问 API key、Realtime 模型名和服务地域。地域可用左右方向键切换，回车确认；默认选择北京。

| 使用哪个地域 | 在向导中选择               |
| ------------ | -------------------------- |
| 中国内地服务 | Beijing / 北京（国内）     |
| 国际服务     | Singapore / 新加坡（国际） |

北京和新加坡的 API key **不能混用**。请在所选地域创建 key，并确认该地域可以使用你选择的模型。获取方式见[官方 API key 指南](https://help.aliyun.com/zh/model-studio/get-api-key)。

向导会自动填写所选地域的服务地址，不必手动拼写。

<details>
<summary>如果只想在配置文件里切换地域</summary>

同时修改 `realtimeApiKey` 和 `realtimeEndpoint`，其他设置可以保持不变：

| 地域   | `realtimeEndpoint` 填什么                              |
| ------ | ------------------------------------------------------ |
| 北京   | `wss://dashscope.aliyuncs.com/api-ws/v1/realtime`      |
| 新加坡 | `wss://dashscope-intl.aliyuncs.com/api-ws/v1/realtime` |

</details>

仅更换同一地域的 API key 或模型时，可以在现有文件中修改：

```json
{
  "realtimeApiKey": "sk-your-api-key",
  "realtimeModel": "qwen3.8-omni-flash-realtime"
}
```

默认主模型是 `qwen3.8-omni-flash-realtime`。使用其他模型或邀测别名时，把控制台提供的**完整 Realtime 模型 ID** 填入 `realtimeModel`，不要直接填写产品宣传名称。已有配置中的显式模型选择优先于默认值，不会自动替换。

### 常用设置速查

| 字段               | 默认或常见值                    | 什么时候需要改                         |
| ------------------ | ------------------------------- | -------------------------------------- |
| `language`         | `"zh-CN"` 或 `"en"`             | 修改固定界面语言；也可直接在设置中切换 |
| `realtimeApiKey`   | 初始化时填写                    | 更换账号或服务地域                     |
| `realtimeModel`    | `"qwen3.8-omni-flash-realtime"` | 更换实时对话模型                       |
| `realtimeEndpoint` | 默认北京                        | 在北京／新加坡服务之间切换             |
| `voice`            | `"Tina"`                        | 修改播报音色，需使用模型支持的名称     |
| `shortcut`         | `"Command+E"`                   | 修改开始／结束交互的快捷键             |

记忆和主动提醒默认也使用所选地域的服务，通常不需要单独设置服务地址。

## 主题配色

在**设置 → 个性化 → 配色**中选择色样，语音卡片和子智能体窗口会立即更新，选择也会保存；无需结束通话或重启。默认配色为雾紫（Iris）。

也可以在配置文件顶层设置：

```json
{
  "themeColor": "iris"
}
```

支持 `iris`（雾紫）、`clay`（暖陶）、`sage`（鼠尾草）、`tide`（潮汐）、`graphite`（石墨）、`rose`（玫瑰）和 `berry`（莓果）。手动修改后，重新打开桌面应用或重新连接后台服务生效；通过设置页选择则立即生效。未设置或取值无效时使用雾紫。浅色、深色和跟随系统的选项在**个性化 → 外观**中单独设置。

## 视觉输入

先选“看哪里”，再选“什么时候看”：

- **视频来源 → 屏幕**：使用电脑屏幕画面。
- **视频来源 → 摄像头**：使用摄像头画面。
- **采集模式 → 按需截图**：需要时才截图，这是默认方式。
- **采集模式 → 实时画面**：通话期间持续发送近期画面，可直接询问“你现在看见什么”。

**按需截图无需接入编程助手。** 询问画面时，“画面分析”子智能体会分析一张截图，再由复用同一模型和音色的独立播报助手回答；主对话保留文字结果，方便继续追问。在**子智能体**窗口中可查看状态和结果，或停止分析；结束通话会取消未完成的分析。它使用主对话的 API key 和地域，不需要另选模型。

遇到服务端重复输出错误、临时网络故障或超时时，画面分析会复用同一张截图和问题，改用更简短的回答格式**重试一次**，不会再次截图或执行后台任务。取消、鉴权或配置错误、无效输入和不安全输出不重试。每次尝试最多 25 秒，两次合计最多 50 秒；重试仍失败时会正常报告。

屏幕的实时画面、按需截图和视觉监控都采集选定显示器的完整画面，而不只是当前窗口。使用多个显示器时，在**显示器**中选择，默认使用主显示器。按需截图不会把图片直接发送给主对话；分析失败也不代表桌面为空白。文件和应用操作仍需接入编程助手。

### 修改帧率和清晰度

默认是 **每秒 1 帧、1280 × 720（720p）**，一般可以先保持不变。提高帧率或分辨率会增加网络和模型用量，也不保证设备能达到设置的速度。

例如，明确使用 1 FPS、720p 的实时画面：

```json
{
  "visualInput": {
    "fps": 1,
    "liveResolution": { "width": 1280, "height": 720 },
    "cameraResolution": { "width": 1280, "height": 720 }
  }
}
```

| 设置                           | 作用                       | 默认值                              |
| ------------------------------ | -------------------------- | ----------------------------------- |
| `visualInput.source`           | 启动时使用屏幕还是摄像头   | `"screen"`；摄像头填 `"camera"`     |
| `visualInput.mode`             | 启动时按需截图还是实时画面 | `"on-demand"`；实时填 `"live-feed"` |
| `visualInput.fps`              | Live Feed 每秒发送几帧     | `1`，可设 `0.1`–`10`                |
| `visualInput.liveResolution`   | 实时画面的目标尺寸         | `1280 × 720`                        |
| `visualInput.cameraResolution` | 摄像头预览和实时视频流尺寸 | `1280 × 720`                        |

尺寸按“宽 × 高”填写，画面会保留原来的宽高比。实际发送时可能进一步压缩或缩小，因此设置更大尺寸不代表一定能看到更多细节。

### 屏幕截图和摄像头截图的尺寸

按需截图有两个独立设置，默认都用设备可提供的原生尺寸：

- `snapshotResolution`：Screen 截图尺寸。
- `cameraSnapshotResolution`：Camera 截图尺寸。

例如，屏幕截图保持原生尺寸，摄像头截图最多使用 1920 × 1080：

```json
{
  "visualInput": {
    "snapshotResolution": "native",
    "cameraSnapshotResolution": { "width": 1920, "height": 1080 }
  }
}
```

这不会同时改变摄像头预览或 Live Feed 的尺寸。`native` 只用于上述两个截图设置。

### 摄像头预览和权限

选择摄像头后默认显示预览。眼睛按钮只控制预览的显示和隐藏，**隐藏预览不等于关闭摄像头输入**。结束通话后可能仍保留本地预览；切回屏幕或退出应用可关闭摄像头。

请按界面提示授予当前来源所需的权限。使用摄像头不需要先授权屏幕录制；屏幕的实时画面和按需截图都需要屏幕录制权限，不需要辅助功能权限。

## Memory：让对话有记忆

记忆默认开启，视觉记忆默认关闭。在**设置 → 个性化 → 记忆**中，可以：

- 开关记忆：关闭不会删除以前保存的内容。
- 选择或新建记忆库：适合区分工作、个人或不同项目。
- 修改记忆库名称。
- 修改记忆整理模型。
- 开关**视觉记忆**。

切换／新建记忆库或修改整理模型前，请先结束通话；改名和开关可以在通话中操作。

### 修改记忆整理模型

整理模型用来提炼值得保留的信息，和负责实时说话的主模型是两个设置。默认是 `qwen3.7-plus`，请使用所选地域可用的模型 ID。

```json
{
  "memory": {
    "enabled": true,
    "updater": { "model": "qwen3.7-plus" }
  }
}
```

如果只想关闭记忆，把 `memory.enabled` 改成 `false`，或直接在设置页关闭。

### 开启视觉记忆

视觉记忆会定期观察所选的屏幕或摄像头，并保存文字描述。默认每 60 秒观察一次：

```json
{
  "memory": {
    "observer": {
      "enabled": true,
      "intervalSec": 60
    }
  }
}
```

观察模型默认跟随记忆整理模型。它需要支持图片输入；如果整理模型只能处理文字，可另外设置 `memory.observer.model`。

视觉记忆和“回答当前画面的问题”是不同功能。单次问题可以用按需截图；通话中持续分享画面则用实时画面。这两种方式都不要求开启视觉记忆。

### 记忆保存在什么地方

默认目录是 `~/.qwen-live-harness/memories/`。通常在界面选择记忆库即可，无需修改文件夹。

需要另存到其他位置时，可以设置：

```json
{
  "memory": {
    "dir": "~/Documents/QwenMemories"
  }
}
```

改目录不会自动搬迁旧记忆。需要迁移时，请先退出应用并备份原目录。记忆以文字为主，不在记忆数据库中保存原始音视频；开启视觉记忆后，采样图片仍需发送给观察模型来生成描述。

## Proactive：主动提醒与观察

Proactive 默认开启。你可以直接说：

- “十分钟后提醒我休息。”
- “观察屏幕，下载完成后提醒我。”
- “看看摄像头里的变化，有新情况告诉我。”

它只会在你创建观察或提醒任务后开始工作。Monitor 不会自行打开网页或定期访问某个网址，但可以监测**屏幕上已经显示的网页**。

如果模型正在说话，主动通知会等待当前播报结束后依次播放。结束通话会停止这次通话中的 Proactive 观察和提醒；它与继续运行的后台 Harness 任务不同。

### 没有听到主动播报时

如果 Proactive 响应正常结束却没有生成语音，Live 最多会尝试一次独立播报，仍使用相同模型与音色。它把 Monitor 的观察摘要说出来，不是重新分析原始媒体，也不需要另选模型。这会增加一次模型调用，但不会增加监控触发次数。

子智能体窗口中的**准备播报**表示还在准备回复；设备确认开始播放后才变成**正在播报**。补充播报收到播放完成确认后才显示**已播报**，未完整播放则显示**未播报**。因此，一次性任务可能已经完成，但通知没有完整播出；重复监控不会因为这一次补充播报失败而停止。

补充播报最多等待模型生成 20 秒，并受该次播报时限约束。排队时会等待前面的回复和工具调用处理完毕；用户说话、关闭播报、取消任务或结束通话都会取消它。被打断的补充播报不会重播。静音时处理过的通知也不会在取消静音后补播，因此任务显示完成不代表通知已被听到。

### 常用 Proactive 设置

```json
{
  "proactive": {
    "enabled": true,
    "monitor": { "representationCompact": "normal" },
    "scheduler": { "evalIntervalSec": 1 },
    "vision": { "windowSizeSec": 10 },
    "audio": { "windowSizeSec": 60 }
  }
}
```

| 设置                                      | 默认值     | 通俗解释                                                       |
| ----------------------------------------- | ---------- | -------------------------------------------------------------- |
| `proactive.enabled`                       | `true`     | 是否开放主动观察和提醒功能                                     |
| `proactive.monitor.representationCompact` | `"normal"` | 视频表征压缩；`normal` 聚合画面表征，`none` 保留更细粒度的表征 |
| `proactive.scheduler.evalIntervalSec`     | `1`        | 每隔几秒检查是否已有完整片段可供下一轮判断                     |
| `proactive.vision.windowSizeSec`          | `10`       | 本地最多暂存最近几秒的画面，防止慢推理积压过多数据             |
| `proactive.audio.windowSizeSec`           | `60`       | 本地最多暂存最近几秒的声音                                     |

Monitor 的媒体节奏**固定为 1 FPS、每轮 2 秒**，与可配置的前台 Live Feed 帧率独立。监控结果存在采样、网络和模型判断延迟，不是每一帧都会立刻触发提醒。

每轮 Monitor 处理 **2 秒**的新内容。纯音频监控发送 2 秒新麦克风音频；视觉监控**每秒采集 1 张新画面**，每轮共两张；音视频监控把这两张图与同一时段的 2 秒麦克风音频一起发送。纯视频监控使用协议所需的静音音轨，不包含麦克风声音。等待 Monitor 回答后再发送下一片段。前面的回答保留在同一模型会话中，不需要反复发送。`windowSizeSec` 是本地暂存上限，不是每轮都重发这么长的内容，也不代表模型会自动忘记更早的会话历史。

Monitor 帧率和片段时长不是配置选项；可以调整本地缓冲、调度、冷却与视觉压缩。两个 `windowSizeSec` 都不能小于 2 秒。视觉或音视频片段需要同一时段内的两张新画面，采集过慢或画面不足会跳过不完整片段，debug 日志会记录原因，不会复制此前的画面凑数。

这个压缩配置只作用于 Proactive 视觉 Monitor，不改变前台 Live Feed 或截图分辨率。默认的 `normal` 适合关注整体变化的监控；需要关注细小文字或画面细节时，可以改成 `none`。On Demand 画面分析使用自己固定的 `normal` 设置。修改后重启 Qwen Live Harness 生效，初始化向导不额外询问此项。

## 要不要接入后台 Harness

只需要语音交流、分享画面、记忆和主动提醒时，可以不安装编程助手。初始化时选择**暂不接入编程助手，继续设置**即可。

需要修改文件、运行命令或完成后台任务时，先按编程助手的官方文档安装并登录，再运行初始化选择它。可选 [Qwen Code](https://github.com/QwenLM/qwen-code)、[Qoder CLI](https://qoder.com/cli)、[Codex](https://developers.openai.com/codex/cli)、[Claude Code](https://code.claude.com/docs/en/setup) 或 [Gemini CLI](https://github.com/google-gemini/gemini-cli)。

如果要在已有配置中明确关闭后台任务委托，可使用：

```json
{
  "backends": []
}
```

请保留这个空数组；省略 `backends` 会选择默认的本机 Qwen Serve 连接，而不是关闭委托。

### 联网查询

无论是否接入编程助手，都可以通过搜索子智能体查询公开信息。它使用主对话的完整模型 ID（包括邀测别名）、服务地址和 API key，无需单独配置搜索模型。应用不按模型名称限制搜索入口，能否联网查询取决于服务端是否支持。

Qwen Omni 会先简短回应，例如“我查一下最新信息”，再在后台搜索。你可以继续对话或提出其他独立查询；多个搜索可并行进行，结果就绪后会等待当前讲话与播报结束，再由复用同一模型和音色的独立播报助手依次回答。视觉、搜索和后台任务结果都使用这条不调用工具、也不再次搜索的播报通路，文字结果仍保留在主对话和子智能体窗口中。被打断的播报不会自动重播。普通聊天、无需联网的问题仍直接回答。

如果搜索请求失败（包括服务端不支持原生搜索），已配置的编程助手会接手同一个只读查询；没有编程助手时，会提示查询失败。转交使用独立任务，不会打断其他正在运行的任务；其授权请求按你选择的全局授权模式处理。

在**子智能体 → 联网搜索**中可查看查询、状态和结果，或停止搜索。成功转交后会另外显示对应后台任务。结束通话会取消搜索及其转交的查询，其他后台任务不受影响；是否已停止，以任务面板显示的状态为准。

在**子智能体**窗口中可以查看或停止任务、处理权限请求。关闭详情窗口不等于停止任务。若编程助手提示“没有文件权限”却没有授权按钮，请检查该助手自身的设置；Qwen Live Harness 只显示它实际发出的授权请求。

### 子智能体中的授权选项

配置完后台 Harness 后，`init` 会询问如何处理它的授权请求。之后可以在**设置 → 后台 Harness 授权**中修改，也可以编辑 `config.json` 顶层的 `permissionMode` 字段：

- **每次询问**（`"ask"`，默认）：查看子智能体中的命令、参数、工作目录和涉及文件，再允许或拒绝当前操作；不再为单条请求选择“以后都允许”。
- **默认允许全部**（`"allow-all"`）：自动批准当前等待及之后的请求。通话中会播报重要操作，`pwd`、`ls`、`git status` 等普通检查只记录、不播报。没有通话时也能继续处理请求，但不会自行开启音频。

每次批准都使用后台的单次选项，不建立后台持久授权；没有单次选项时，会取消并说明原因。自动授权播报只表示批准已送达，不代表命令已经开始或执行成功。切回**每次询问**会停止后续自动批准，但不会撤销已经发出的批准。后端自身限制仍然生效，Live 只处理后端实际发出的授权请求。

旧开发版本可能留下 `permission-policies.json`，现在会忽略该文件并保持原样，切换模式不需要删除它。若编程助手已有自己的原生持久授权，请在该助手设置中另行撤销。开发者细节见[语音授权与持续允许](../packages/qwen-live-harness/README_ZH.md#语音授权与持续允许)。

## 哪些界面设置会保存

- **视频来源／采集模式**立即影响当前运行，但不会写入配置；想改变下次启动的默认值，请修改 `visualInput.source` / `mode`。
- **显示器、语言、记忆、后台 Harness 授权**的已确认设置会保存。
- **后台 Harness 授权**会保存到 `config.json`，设置确认成功后立即生效，也会处理已经等待的请求。
- 麦克风选择、外观和窗口位置由本机桌面应用保存；配色保存在 `config.json`。
- 手动编辑配置文件后，都需要完整退出并重新启动。

## 常见问题

**改完配置没有生效？** 先确认保存了文件，并完整退出再启动。如果以前设置过环境变量，它会优先于配置文件，例如 `QWEN_LIVE_HARNESS_REALTIME_ENDPOINT` 会覆盖文件中的地域地址。

**提示 API key 或模型不可用？** 检查 key 和 Endpoint 是否属于同一地域，再确认填写的是该地域可用的完整模型 ID。

**提示 Realtime 配额受限？** 在服务商控制台检查所选地域的账户配额和并发会话。结束不用的会话可能释放并发，但账户额度不足需要在服务商侧处理，反复重启不能解决。

**没有声音或一直显示“正在启动”？** 检查麦克风权限，在**设置 → 声音 → 麦克风**选择一个可用设备，再点击开始通话。等待当前操作完成或报错后再重试。

**蓝牙耳机打开麦克风后，音乐音质变差？** 可在**声音 → 麦克风**选择电脑内置或独立麦克风，继续用蓝牙耳机播放声音。模型输出使用 24 kHz PCM，发送给模型的麦克风音频为 16 kHz；播放时会转换到输出设备的实际采样率。调整软件采样率不能避免蓝牙耳机切换到低音质通话模式。

**只想结束通话？** 点击结束通话或按 `Command+E`，本次画面分析、主动监控、搜索及其转交的查询也会取消。要关闭整个应用，请选择**退出 Qwen Live Harness**；从终端启动时也可按 `Ctrl+C`。

### 需要更多日志时

```sh
qwen-live-harness --debug
```

从源码运行时，在仓库根目录使用：

```sh
npm start -- --debug
```

debug 会打印更详细的运行信息，并在 `<dataDir>/debug/run-*` 下创建本次运行归档，默认位置为 `~/.qwen-live-harness/debug/run-*`，日志会显示具体目录。归档关联模型请求／响应、工具与运行事件，以及对应通路实际处理的声音和图片。它不是设备的连续录音或录像，未开启 debug 时的媒体无法事后补录。

默认保留最近 **10 次已结束的运行归档**，**每次归档预算为 512 MiB**。正在运行的归档不会被清理，因此目录总数可能暂时超过十个。达到存储上限、记录丢失、文件缺失或写入失败时，归档可能不完整；分析前先看 `manifest.json` 和警告日志，不能把缺失部分当成没有发生。这些诊断故障不应导致交互停止。

逐 Monitor 媒体归档独立位于系统临时目录的 `qwen-live-harness-monitor-debug/`，日志会显示具体位置。所有模态合计保留最近创建的 **10 个 Monitor**，不是只保留 10 次请求，也不是固定的磁盘容量上限。需要逐轮分析时，见开发者指南中的 [Monitor 诊断归档](../packages/qwen-live-harness/README_ZH.md#monitor-诊断归档)。

Debug 会保存真实私密声音、屏幕／摄像头画面、Prompt、Memory 上下文、工具参数／结果及对话文字。已知凭据会脱敏，但不代表私人内容或媒体中的秘密也被匿名化。分享前逐项检查，不要直接上传整个数据目录。问题排查完后建议关闭 debug。

离线校验和导出指定模型连接的方法，见 [运行归档与离线检查](../packages/qwen-live-harness/README_ZH.md#运行归档与离线检查)。辅助工具不会调用 API 或执行记录里的任务，也不能保证未来模型生成完全相同的回答。

源码启动、开发调试见 [Daemon 开发指南](../packages/qwen-live-harness/README_ZH.md)。如果需要自定义后端、完整环境变量列表、Memory 检索参数或其他高级选项，请查看[高级配置参考](../packages/qwen-live-harness/README_ZH.md#高级配置参考)。
