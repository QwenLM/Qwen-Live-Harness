# 视觉分析、任务委托与会话可靠性

[English](live-image-handoff-reliability.md)

## 职责与范围

Host 采集选定显示器或摄像头，daemon 管理主对话、独立模型连接、工具执行与结果队列。On Demand 视觉问题交给只读 Omni Realtime 子模型，它复用主对话配置的模型、endpoint 和 API key，不需要后台编程 Harness。Live Feed 持续把画面直接交给主模型；明确的文件、命令或应用操作交给配置好的后台。

这些通路分别管理媒体、任务、响应与播放身份。截图资产不代表模型已经理解画面，socket 写入成功不等于服务端确认收到，任务受理也不等于任务完成。

## 按需视觉分析

1. 主 Omni 调用 `appshot`，最终响应完成并确认函数 ID 和参数后才执行。可选参数 `query` 指定视觉问题；省略时使用关联的真实用户请求，或概述画面的默认问题。
2. Host 捕获选定显示器的完整画面并排除自身窗口，或采集所选摄像头。截图结束时若通话已结束或来源已变化，则拒绝该结果。屏幕资产保留原生 PNG，摄像头资产保留 JPEG 字节与 MIME。
3. 运行时创建 Visual Analysis 子任务，返回 `accepted + taskId`、截图元数据及可用的资产句柄。回执仅说明任务已受理，不是视觉答案。多个独立分析可并行执行。
4. 子模型收到 JPEG 和问题后，根据可见像素返回文字。它没有自定义工具、联网搜索、后台操作能力、Memory 上下文或无关对话历史；截图内的指令文字是不可信内容。
5. 分析结果进入只读结果 FIFO，等待前台对话和设备播放结束，由主 Omni 组织答复。这类通知不能授权新的工具或操作；静音或没有语音时，Subagents 仍保留结果。
6. 分析总期限为 25 秒，握手最多八秒。Stop 或 End call 取消未完成分析并撤回待播结果。分析失败不自动转交编程代理，也不代表桌面是空白的。

### 子模型媒体协议

子模型发送一次 `session.update`，设置固定系统指令、纯文本输出、`voice: Tina`、`smooth_output: false`、`turn_detection: null`、空工具、关闭搜索以及 `normal` 视觉表征压缩。输入排布如下：

```text
append 1 秒静音 PCM16 / 16 kHz
append 当前静态 JPEG
append 1 秒静音 PCM16 / 16 kHz
append 同一张静态 JPEG
input_audio_buffer.commit
等待 input_audio_buffer.committed
response.create，在 response.instructions 中携带图片问题
```

重复图片用于满足媒体协议，不代表发生了运动或进行了两次独立观察。静音是协议载体，不是麦克风证据；`response.instructions` 承载本次手动媒体请求的问题，不是子模型系统 Prompt。

主连接在整个过程中保持 semantic VAD，不接收这次截图的像素、不切换 manual 模式、不提交截图音频缓冲，也不为视觉子模型暂存麦克风输入。

## 明确的图片委托

- `session_create` 创建后台会话，回执不声称已提交工作；`handoff` 使用真实会话句柄提交用户要求的任务。
- 工具的附件字段是 `input_refs`，类型为资产句柄数组。字段不是数组、元素不是字符串，或任一资产未知、过期、不可读、内容为空，都会在提交任务前以 `image_unavailable` 拒绝整个 handoff，不悄悄提交部分附件。
- 有效资产保留字节与 MIME；JPEG 附件使用 `.jpg`，PNG 使用 `.png`。
- 声明不支持图片输入的后台可以只接收文字，但回执必须明确给出警告，助手不能声称图片已送达。只收文字的终端指令通路拒绝附件；支持图片的后台收到经过校验的图片块。
- 主对话按当前交流语言说明警告和错误，不因重复确认抑制而隐藏这些信息，也不另行插入写死的英文播报。

## 指令、权限能力与工具回执

主会话系统指令在整场通话中不变，每条 transport 仅在 `session.update` 发送一次。来源与采集模式变化通过静默 `[VISUAL_INPUT]` 上下文传入；Memory 变化通过可替换的 `[MEMORY_CONTEXT]` user 快照传入，关闭时发送不含旧数据的禁用快照。工具列表变化只使用 tools-only `session.update`，不会改写主系统 Prompt。子 agent 结果以带类型标记和引用数据的 `conversation.item.create` user 上下文消息传入，不构成新的用户授权。

服务端拆分尚未取消的回答，且没有更新的用户输入取代它时，真实用户输入保留对应工具权限；内部通知不能获得该权限。执行工具前，最终函数快照的 ID、名称、参数与完成状态必须一致。

每份异步受理回执都需得到确认，并由独立 `tool_continuation` 消费后，才能注入最终任务结果。只有工具链已经产生音频，且同一响应中的所有工具都成功受理了符合条件的异步任务时，才抑制重复确认音频。文字保留在服务端历史与诊断转录中，不作为用户听到的对话进入 Memory、委托上下文或重连历史。错误、警告、混合查询工具，以及没有音频铺垫的受理确认照常播报。

确认续答若重复完全相同的已受理任务，会复用原回执，不再启动任务；该保护仅作用于对应回执续答，不合并不同请求或真实用户的新一轮请求。已被取代的回执单独静默消费，不继承先前轮次的工具权限。能够精确关联的函数结果拒绝或未确认状态会终止该续答链，不重新执行动作；其他协议错误按各自规则处理。

## 授权与有限恢复

新的后台权限请求按当前真实对话语言询问一次。用户打断、换话题或要求等待时，保留静默待审批上下文，不定时催问。只有与相关权限 ID 绑定的明确用户决定才能授权 `respond_permission`；任务文字、截图内容与通知结果都不能代替审批。

响应状态恢复由 recovering-session 层统一管理：先隔离退役 transport，再打开替代连接，**每次逻辑通话最多尝试两次替代连接**。Host 通话、后台任务、Monitor、Memory attachment 以及待处理权限／结果保持各自生命周期，不被重新创建。

只恢复尚未派发工具且能安全保留的输入：完整用户文字，或具有可信起点的有界真实麦克风音频。静音心跳与视觉子模型的协议静音不进入这类音频。已经派发的工具与退役函数回执不重放；恢复上下文携带当前任务、Memory、视觉和权限状态，先前的审批不能转移到恢复期间出现的另一项权限请求。

空闲的新连接可以忽略没有 ID 的完成事件；正在等待响应确认时，缺少 ID 仍是协议错误。输入无法安全恢复时，UI 提示用户重复；恢复次数耗尽则明确结束交互。这不是无限重连策略，也不是外部后台动作的 exactly-once 保证。

## 诊断与验证

Debug 运行归档保留观察到的主模型／子模型 wire 事件、媒体引用、工具／控制事件及可用的服务端 Session ID。检查与连接导出只离线执行，不重跑工具或上传媒体，见[运行归档与离线检查](../../packages/qwen-live-harness/README_ZH.md#运行归档与离线检查)。容量限制或存储故障可能留下不完整证据；凭据脱敏不能清除图片像素或声音中的秘密。

测试应覆盖答案只存在于像素中的不同合成图片、屏幕／摄像头切换、无后台使用、截图取消、子模型失败、并行分析、结果 FIFO 和真实播放回执。附件测试覆盖 MIME、无效与部分可用引用、不支持图片的后台，以及文字终端拒绝附件。

协议测试还应覆盖连续响应拆分、用户打断、迟到回调、确认／取消超时、静默回执消费、审批等待、两次恢复机会及 Stop／End call 竞态。合成传输测试或单次模型成功不能证明全部真实设备与服务商行为可靠。
