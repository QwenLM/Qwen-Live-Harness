# Live 对话与图片交付可靠性

[English](live-image-handoff-reliability.md)

## 问题

此前按需截图只向前台 Realtime 模型返回本地图片引用，没有提供像素。即使简单视觉问题也需要另行委派后台，前台可能口头承诺分析却没有提交任务。服务端拆分工具后续响应时，还会丢失原始用户的工具权限。此外，图片过期后，交付链路会悄悄省略附件。

## 行为

- 服务端拆分尚未取消的响应，且没有更新的用户输入取代它时，保留已有用户工具权限及输入身份。内部通知不能获得该权限。
- 使用现有 Host 按需采集屏幕或摄像头，将该帧直接发送给当前 Realtime 连接，再返回 Appshot 结果。普通视觉问题直接回答，没有后台时也适用。Live Feed 行为不变。
- 成功回执说明图片已向 Realtime 发送，不宣称模型已经正确理解。回答依据最新实际图片，不能依据尺寸、旧帧或附件引用推断内容。屏幕辅助功能文本保留为补充依据；只有明确委派的后台工作才需要图片 handoff。
- 截图完成时若工具请求、通话、Realtime 连接或视觉设置已失效，拒绝发送。图片发送失败时返回错误，不返回成功回执，也不自动委派后台。
- 创建会话的回执明确说明尚未提交任务；用户要求执行工作时，下一步是 handoff。
- 任何指定图片引用不存在、过期、无法读取或内容为空时，整个 handoff 返回 `image_unavailable`，不提交附件不完整或只有文字的任务。通过现有语音队列，在当前响应结束后播报失败；仅返回回执不会恢复 handoff 响应。
- 保留 JPEG 字节和 MIME，摄像头附件使用 `.jpg` 文件名；屏幕 PNG 保留 `.png`。

## 按需图片提交

当前 provider 拒绝在语音提交后没有新音频的情况下追加图片；持续静音 PCM 加图片 append 虽无协议错误，也没有产生正确内容答案。独立图片消息在该端点同样失败。相反，单独手动提交媒体、等待其空转写完成后，同一连接的三张不同图片均得到正确回答。

对仍有效的 Appshot 调用，暂时关闭自动语音检测，追加一秒零 PCM 与 JPEG 后一起 commit。期间到达的麦克风 PCM 在本地暂存，复用现有 1 MiB 上限。媒体提交标识单独登记，不当作真实语音输入；等待该媒体项的空最终转写后，恢复 semantic VAD，按顺序发送暂存麦克风数据，再完成原工具回执。这是媒体输入，不是新用户发言或工具授权；不会重放用户音频或文本来强行触发新轮次。

拒绝失效请求和并发媒体提交。若提交期间收到语音开始事件，或媒体项出现非空转写，输入归属无法确定，明确报错并请用户重复。发送失败、连接关闭、缓冲溢出或十秒超时会结束图片请求，必要时关闭该连接。设置切换或响应取消会使成功回执失效，已发送的媒体事务仍可完成麦克风恢复。已识别的媒体事件不进入字幕、对话记忆和用户输入仲裁。

## 会话状态与恢复

- 切换视觉来源或采集模式时，同时刷新会话系统指令与静默状态。后续响应不能继续携带旧的 Screen / Camera 设置。
- 首次授权请求照常询问。之后用户打断、换话题或要求等待时，仅保留静默授权上下文，不定时重复催问；只有明确用户决定才能调用授权工具。
- 用户明确要求新建任务时，工具说明和系统指令统一要求创建会话并提交任务，不能用普通搜索或口头承诺替代。这仍需真实模型行为验证。
- 空闲新连接收到没有 response id 的完成事件时忽略它。存在尚未确认的请求时，该缺失仍属于协议错误。
- 沿用 0.4.4 主分支的统一传输恢复层处理响应状态丢失，不再增加第二套编排层重连。Host 通话、后台任务、授权状态、待注入结果及 Memory 对象继续保留；恢复最多尝试两次，旧连接回调、截图及异步工具结果不能进入新连接。
- 恢复层仅续接尚未执行工具且可安全还原的用户文字或音频；已经派发的工具不重放。无法还原的输入在界面提示用户重复，恢复失败明确结束通话。静音心跳与图片提交的零 PCM 不进入可重放的真实麦克风数据。

## 边界

不引入新进程、provider、模型、媒体权限、自动采集或永久图片归档。按需图片现在发送给已经接收实时语音与 Live Feed 的同一 Realtime provider，复用现有 JPEG 通道与尺寸限制。普通视觉问题的图片推理计费由配置的后台转移到当前 Realtime 模型，费用差异尚未测量。可选本地图片附件仍供明确委派的后台任务使用，临时文件生命周期不变。沿用主分支恢复层的两次连接尝试上限，不重复执行后台任务。回执提示改善模型行为，但不构成模型必然遵从的保证。

## 验证

覆盖普通及连续响应拆分、新用户打断、取消和内部通知权限边界。首先用真实 provider 确认在 Appshot 调用后单独提交的图片能被后续响应读取。期望答案只能存在于合成图片像素中，不能出现在提示词、辅助功能文本、文件名或回执里。验证连续不同截图、屏幕与摄像头切换、无后台运行、发送失败与过期采集拒绝。WebSocket 发送成功不等于看图成功。继续验证显式图片 handoff 以及缺失或部分可用附件的拒绝。真实私人照片不进入跟踪文件，诊断副本在检查后清理。

验证取消超时的两种时序、恢复失败、再次超时、停止与重连竞态、旧连接输出隔离、未提交输入和待授权状态保留。连续真实模型场景包含新建任务、授权后换话题、切换摄像头、图片交付和后续授权。合成传输或单轮模型成功不能证明全部用户流程正常。
